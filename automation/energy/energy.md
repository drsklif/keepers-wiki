# Автоматизация бесплатной энергии

## Цель

Забирать бесплатную энергию во всех доступных окнах, не пропуская их, пока открыта вкладка с игрой.

Расписание **не зашито в скрипт**. На старте оно читается из живого клиента:

1. `CFGUtil.getQuestName` / `QuestsPage.create` — базовые часы + `user.gmt`;
2. список `user.quests.quests` — имя «с X:00 до Y:00» и поля квеста, если сервер их прислал.

## Как устроено в клиенте

Источник: `CFGUtil.getQuestName`, `UserUtil` (список квестов), `QuestsPage` (UI и команда).

- Ежедневные квесты лежат в `app.Model.user.quests.quests`.
- Название: «Получи бесплатную энергию с X:00 до Y:00».
- Квест **активен и можно забрать**, когда `progress >= required` и награда ещё не взята (`rt` пустой/0).
- Кнопка в UI: **«Получить»**. Пока окно не открылось — только таймер.
- Таймер на строке (Москва + `gmt`):
  - до окна — «Через: …»
  - внутри окна — «Сейчас»
  - после окна, если не забрали — «Завтра» (квест остаётся в списке, но неактивен)
- Клик «Получить» шлёт `UserQuestComplete` с `{ quest: <id> }`. Энергия приходит в `quest.reward.energy` и добавляется **после** выполнения.
- Когда квест становится выполненным, зелёная точка на вкладке «Задания» загорается. Сервер также может прислать `UPDATE` по `user.quests` и/или `GAME_MESSAGE`.

Сервер — источник истины для получения: забирать можно только если модель уже пометила квест выполненным. Локальные часы нужны только для статуса «через / сейчас / завтра».

## Требования к скрипту

- Tampermonkey-модуль KeepersHelper.
- Без окон заданий: по `UPDATE` / `GAME_MESSAGE` / поллу модели слать `UserQuestComplete`.
- Счётчик энергии наверху — штатный HUD `MainPage.resources.energy`. Клиент сам обновляет его по цепочке `command.user` → `UPDATE_USER_DATA` → `user resources changed`. Скрипт после ответа ещё раз эмитит это событие (и дописывает `energy.v`, если сервер не прислал новое значение).
- Бой не открывает и не закрывает. Команда уходит и во время боя.
- Переключатель «Энергия» в оверлее (без широкой статусной строки; окна в tooltip и в логе), по умолчанию включён, состояние в `localStorage`.

## Что проверить по HAR (когда будет)

Текущие HAR, скорее всего, не содержат это окно. Полезно снять WebSocket около открытия окна:

1. `UPDATE` с обновлением `user.quests.quests[]` (тип, `progress`, `required`, `rt`, `reward.energy`, любые поля времени).
2. `GAME_MESSAGE` в момент активации (текст тоста).
3. Ответ на `UserQuestComplete` (награда, новая энергия, ошибки если окно уже закрылось).

Команда и UI уже известны из `QuestsPage`; HAR нужен, чтобы подтвердить серверный пуш и точный текст сообщения.

## План

1. На старте снять каталог окон из клиента и списка квестов.
2. Детектор: полл модели + `UPDATE_USER_DATA` / `UPDATE` / `GAME_MESSAGE`.
3. Когда квест claimable — `UserQuestComplete`, затем обновление верхнего счётчика энергии.
4. Статус окон — в консоли и в tooltip кнопки «Энергия».
